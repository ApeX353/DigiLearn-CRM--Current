One guided walkthrough that exercises **every** feature built for the
`TEST-BACKLOG-2026-07-30.md` items. Run it on **staging** after deploying
`dube-upgrades`. Roughly 20–30 min. Each step says what to do and the
**expected** result; if any expected result is wrong, note the step number.

## PART A — Campaign, date fix, import gate, dedup  *(items #16, #17, #1–4, #6a)*

**A1. Create a campaign + date format (#16).** As Kim: Campaigns → New
campaign → name "NASH 2026", type Conference, pick a **Start date**.
✅ Under the date box it spells the date out **and** shows `dd/mm/yyyy`
(e.g. "15 August 2026 (15/08/2026)") — no US month/day confusion. Create it.

**A2. Edit the campaign (#17).** Open the campaign → **Edit** → change the
start date → Save. ✅ The header shows the new date. *(This is the fix for
"the date can't be corrected".)*

**A3. Import into the campaign — the gate (#1, #6a).** In the campaign, click
**Import Leads** → choose the NASH xlsx → wait.
✅ It says **"Staged for approval — N ready, X possible duplicates"** and
explicitly **"Nothing has been added to the CRM yet."** Nothing appears under
Sourced leads or in the Leads list.

**A4. Prove the double-import can't happen (#3).** Click **Import Leads** and
upload the **same file again**. ✅ A second pending batch is staged and **every
row is flagged as a duplicate** (existing/ within-batch). Nothing doubles.

**A5. Review + approve (#3, #4, #2).** Approval Queue → **Import approvals**
tab. ✅ Both batches listed with "N ready / X dup / total" counts. Open the
first → ✅ a table of rows with **duplicate/invalid flags**; dupes default to
**Skip**. Toggle one flagged row to **Include**, then **Approve**.
✅ Toast "created N leads". Open the second (all-dupes) batch → **Reject**.
✅ Nothing created from it.

**A6. Attribution (#2/#6a).** Back in the campaign → **Sourced leads**.
✅ The approved leads appear here (attributed to the campaign).

Queue → Auto-assign → pick a batch size → Run).

✅ Click **Manake** → the table filters to only Manake's proposals; click

pick a different rep. ✅ Toast "Lead redirected and assigned"; the lead is
assigned to the rep you chose, not the engine's pick.

## PART C — Review requests + Enquiry  *(items #13, #12)*

**C1. Rep requests a disqualify (#13).** Log in as the **rep** (Manake). Open
one of their leads → request a **tactical disqualify** with a **reason**.
✅ It's submitted as a pending request (not disqualified outright).

**C2. Manager raises an Enquiry (#12).** As **Kim**: Approval Queue →
**Pending** tab → find that request → **Ask for info** → type a question
("Why no budget?") → send. ✅ Row shows **"Awaiting rep reply"** and the
question in the thread.

**C3. Rep answers (#12).** Log in as the **rep** → open the **Leads** page.
✅ A banner at the top: *"Your manager asked for more info…"* with the
question. Type an answer → send. ✅ Toast "Response sent".

**C4. Manager decides (#12).** As **Kim**: the request's thread now shows the
rep's answer and the "Awaiting rep reply" badge is gone. ✅ You can **Ask for
info again** (repeat C2–C3) or **Approve / Reject**.
